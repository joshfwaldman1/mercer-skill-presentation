# Source protocol

How to establish, cite and check facts from a case file. Read this before making factual claims from the record.

## 1. Inventory first

Make three lists and show them to the student:

1. **Read**: files you opened and whose content you actually processed.
2. **Listed only**: files you can see but have not opened, or opened only partly. Say which pages.
3. **Not machine-readable**: scans or images with no text layer. Any content you report from these comes from a visual transcription, and it must be checked (section 4).

Update the lists as you go. If you later rely on a file from list 2, read it first. Never describe the content of a file you have not read.

## 2. Locators

Every material factual claim gets a locator a reader can open: the file name (or the code the materials use) plus page, paragraph or section. If the course or firm materials define a locator format, use it exactly. Quote short phrases when exact wording matters (admissions, standards, deadlines, a characterization the other side will rely on).

If you cannot find a locator, the claim is OPEN, not VERIFIED. Do not invent page numbers.

## 3. Labels

| Label | Meaning | Required content |
|---|---|---|
| VERIFIED | Checked against the source at the locator in this session | The locator |
| INFERRED | Your reasoning from verified facts | The reasoning, in one line |
| OPEN | Not established by the file | What would establish it, and who has it |
| CLIENT-ONLY (or the course's marker, e.g., [M]) | Rests only on the client's own account | Whether any other source supports it, contradicts it, or is silent |
| A1, A2... | A working assumption where the file is silent | What depends on it, and what happens if it is wrong |
| HYPOTHETICAL | A test condition, not a case fact | Kept separate from the record in every document |

Keep **source status** separate from **dispute status**:
- Source status: the document itself (DT); a recorded action of a body (RA); one person's attributed assertion (AA); an inference (INF).
- Dispute status: is the fact contested, by whom, and on what basis?

**Opposing-party assertions are not facts.** When a notice, report, regulatory filing or form prepared by one side characterizes what happened (e.g., that a person "was afforded" a right, or that a finding was "substantiated"), cite it as that party's assertion (AA). Do not repeat it in your own voice as fact. This trap is common because such documents look official.

**When sources conflict, don't pick one silently.** Show both, with locators, and say which is stronger and why: who wrote it, when, whether it was made for this dispute. Then run the pivot test (SKILL.md Stage 3). If the conflict moves the strategy, it goes on the gaps list with the step that would resolve it. If it contradicts something already in the working documents, run the revision protocol.

**Client-only facts get checked against every later release.** When new documents arrive, revisit each client-only fact and record whether the new material supports, contradicts or says nothing about it. Contradiction of the client's own account is one of the most strategy-relevant things that can happen; flag it immediately (Stage 6).

## 4. Scans, images and handwriting

A visual transcription can be accurate word for word and still be wrong in the ways that matter legally. Before relying on a transcription of a scan, check it against the image for:

- **Typed versus handwritten text.** Record which parts are printed and which are handwritten. Labels, names or headings typed onto handwritten notes were added by someone, at some time; that goes to authorship and reliability.
- **Attribution scope.** If a speaker label sits next to a brace or bracket, the label covers every line in that block, not just the line beside it. Attach it to every line.
- **Insertions and strike-throughs.** Mark words written above the line and words struck out. An inserted "not" can reverse a sentence.
- **Dates and numbers as they appear on the face of the page.** If a digit is illegible, say so; do not fill it in from the file name.
- **Layout.** Braces, arrows, margins and marginalia carry meaning; represent them.

Produce a corrected transcription with these marks, and an error log of what the first pass got wrong. Then return to the map and say what the corrections change: for example, whether a statement is now attributed to a different person.

## 5. Materials known only by description

When a document (for example a summary memo) describes materials that are not in the file, use only what the description says (its counts, categories and dates), cite the description, and do not reconstruct the underlying materials. The underlying materials are OPEN.

## 6. Deadlines and clocks

For every clock show: the rule and its locator; the event that starts it (and any competing start date); the arithmetic; the resulting date; and its status as of the problem's "as of" date. Check day-counting conventions (whether the start day counts) and show both results when they differ. When two documents give different dates for the same event, compute the clock both ways. A date conflict that moves a deadline across an event is a pivotal fact (Stage 3).

## 7. Legal authorities

- Rules contained in the case file (bylaws, contracts, policies): quote and cite them by section and page. These can be VERIFIED from the file.
- External law (statutes, regulations, cases): give the citation and say how it was checked. If you reached the primary source with a tool in this session, say so and cite where. If you are stating it from general knowledge, label it "unverified, from general knowledge" and put it on the research list.
- If a proposition is pivotal and unverified, say how the recommendation would change if it turned out wrong.
- Never fabricate a case name or citation. "Research needed: whether X" is a correct answer.
